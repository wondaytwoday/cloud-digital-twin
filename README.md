# Cloud Atlas

AWS, Azure, GCP의 자원, 네트워크, IAM, 비용을 읽기 전용 API로 수집해 한곳에서 보는 멀티클라우드 운영 포털 프로토타입입니다.

| 화면 | 내용 |
|---|---|
| 개요 > 대시보드 | 자원·상태·비용·조치·보안·네트워크·VM 용량·클라우드 변경·포털 접근을 한 화면에 요약 |
| 개요 > 조치 항목 | 전체 조치 목록, 심각도와 영역 필터, 검색 |
| 개요 > 변경 이력 | 직전 수집과 이번 수집의 차이 |
| 인프라 > 토폴로지 | 연결 지도, 경로 추적, 단절 영향 |
| 인프라 > 리소스 | 분류별 현황 차트, VM vCPU·메모리·디스크·GPU 용량과 사용률, 전체 자원 목록 |
| 인프라 > 네트워크 | 사내망 연결, 피어링, 대역 중복 |
| 보안 > 노출·방화벽 | 공인 노출 후보, 방화벽 규칙 |
| 보안 > 접근 로그 | 포털에 누가 접속해 무엇을 봤는지, 클라우드에서 누가 무엇을 바꿨는지 (최근 7일) |
| 보안 > IAM | 주체별 역할 할당, 특권, 외부 주체, MFA, 오래된 키 |
| 비용 | 원화·달러 선택(섞지 않음), 월별 추이, 클라우드별 비중, 서비스와 범위별 비용, 급증 항목, CSV |

클라우드와 관리 범위 선택은 모든 화면에 함께 적용됩니다. 조직 계층과 클라우드별 연결 상태는 범위 필터의 `관리 범위 전체 보기`에서 봅니다.

처음 접속하면 연결 가이드가 열리고, 닫으면 목데이터로 전체 화면을 볼 수 있습니다. 실제 데이터는 [직접 실행](#실제-데이터로-실행)해야 수집합니다.

> 수집기는 아직 실제 클라우드 계정으로 실행한 적이 없습니다. 기본 실행은 API 응답 형태의 목데이터를 같은 수집·정규화 코드로 보여줍니다.

```bash
npm install
npm run dev
```

## 실제 데이터로 실행

> **Vercel 배포본은 수집하지 않습니다.** https://cloud-digital-twin.vercel.app 은 목데이터 데모입니다. Vercel 환경 변수에 자격 증명을 넣어도 수집되지 않습니다. 함수가 오래 실행되지 않고 결과를 저장할 파일 시스템도 없기 때문입니다. 수집은 클라우드에 접근되는 PC나 서버에서 실행합니다.

### 1. 자격 증명 설정

쓰는 클라우드만 설정하면 됩니다. 일부만 설정해도 그 클라우드부터 수집합니다. 값은 프로젝트의 `.env` 파일에 넣거나 터미널에서 내보냅니다. `.env`는 git에 올라가지 않습니다.

```bash
cp .env.example .env
```

| 클라우드 | 방법 (하나만) | 빠른 시작에 필요한 권한 |
|---|---|---|
| Azure | `az login` 또는 `.env`의 `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET` | 구독의 Reader |
| AWS | `aws login`, `aws sso login --profile <프로필>`과 `.env`의 `AWS_PROFILE`, 또는 `.env`의 `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | ReadOnlyAccess |
| GCP | `gcloud auth application-default login`과 `gcloud auth application-default set-quota-project <프로젝트>`, 또는 `.env`의 `GOOGLE_APPLICATION_CREDENTIALS` | 프로젝트의 Viewer와 Cloud Asset API |

값을 찾는 순서는 터미널 환경 변수, `.env.local`, `.env`입니다. 조직 전체를 읽는 역할 구성은 화면의 `클라우드 연결` 가이드에 있습니다.

### 2. 연결 확인

자원을 읽지 않고 자격 증명만 확인합니다. 안 되면 클라우드별 사유를 표시합니다.

```bash
npm run check
```

### 3. 서버 실행

```bash
npm run live
```

터미널에 표시된 주소를 엽니다. 기본은 http://127.0.0.1:4317 이고, 이 포트를 다른 프로그램이 쓰면 다음 포트로 실행합니다. `npm run dev`와 `npm start`는 목데이터 모드라서 자격 증명이 있어도 수집하지 않습니다.

서버는 시작할 때 수집하고 1시간마다 다시 수집합니다. 아직 수집에 성공하지 못한 클라우드가 있으면 재시작할 때마다 다시 시도하므로, 자격 증명을 바꾼 뒤에는 서버를 재시작하면 됩니다. 실행 중에는 상단의 `수집 상태`에서 클라우드별로 지금 읽는 단계와 항목, 진행률, 실패 사유를 볼 수 있고 `지금 수집`으로 바로 실행할 수도 있습니다. 같은 내용이 터미널에도 출력됩니다.

권한이 없는 서비스나 범위는 건너뛰고 화면에 `일부 누락`과 이유를 표시합니다. 수집 전체가 실패하면 마지막 성공 스냅샷을 유지합니다.

### 수집이 안 될 때

| 증상 | 해결 |
|---|---|
| 웹사이트에 목데이터만 보임 | Vercel 배포본은 수집하지 않습니다. 클라우드에 접근되는 PC나 서버에서 `npm run live`를 실행하세요. |
| 자격 증명을 넣었는데 목데이터가 보임 | `npm run dev`와 `npm start`는 목데이터 모드입니다. `npm run live`로 실행하세요. |
| `로그인 필요`로 표시됨 | 화면에 표시된 사유를 확인하고 `npm run check`로 다시 확인하세요. 값을 바꾼 뒤에는 서버를 다시 시작해야 합니다. |
| 주소를 열었는데 다른 화면이 나옴 | 4317 포트를 다른 프로그램이 쓰면 다음 포트로 실행합니다. 터미널에 표시된 주소를 여세요. |
| `일부 누락`으로 표시됨 | 권한이 없는 항목만 건너뛴 상태입니다. 상단의 `수집 상태`에서 어느 단계가 실패했는지 확인하세요. |
| Azure `AADSTS7000215` | `AZURE_CLIENT_SECRET`에 비밀 ID를 넣은 경우입니다. 비밀을 만들 때 한 번만 표시되는 값을 넣으세요. |
| AWS 로그인 세션 만료 | `aws login`이나 `aws sso login` 세션은 시간이 지나면 끝납니다. 다시 로그인한 뒤 서버를 재시작하세요. 계속 수집하려면 역할이나 액세스 키를 쓰세요. |
| GCP 쿼터 프로젝트 오류 | `gcloud auth application-default set-quota-project <프로젝트>`를 실행하세요. |
| GCP API가 꺼져 있다는 오류 | 해당 프로젝트에서 `cloudasset.googleapis.com`을 켜고 몇 분 뒤 다시 수집하세요. |

### 인증만으로 되지 않는 것

- 읽기 권한은 계정에 미리 있어야 합니다. CSP별 절차와 권한은 화면의 `클라우드 연결` 가이드에 있습니다.
- GCP는 Cloud Asset API가 켜져 있어야 하고, 비용은 BigQuery 결제 내보내기가 필요합니다.
- AWS 조직의 다른 계정까지 읽으려면 계정마다 읽기 전용 역할을 만들고 `ATLAS_AWS_ROLE_NAME`에 그 이름을 지정해야 합니다. 지정하지 않으면 로그인한 계정만 수집합니다.
- AWS S3, Lambda 같은 나머지 서비스 목록은 Resource Explorer 인덱스가 켜져 있어야 합니다.
- Cost Explorer와 BigQuery는 조회할 때 요금이 듭니다. 그래서 비용은 기본 하루 한 번만 읽습니다.
- 사내망은 CSP API로 알 수 없어 아래 형식으로 직접 등록합니다.

범위를 좁히거나 서버 없이 한 번만 수집할 수도 있습니다.

```bash
npm run collect
```

```bash
npm run collect -- --provider aws --regions ap-northeast-2
```

| 환경 변수 | 용도 |
|---|---|
| `DATA_MODE` | `mock`(기본) 또는 `live` |
| `PORT` | 서버 포트. 지정하면 그 포트로만 실행 (기본 4317, 사용 중이면 다음 포트) |
| `ATLAS_HOST` | 바인딩 주소. 기본 `127.0.0.1`. `0.0.0.0` 등 공유 주소에서 실제 데이터를 제공하려면 `ACCESS_TOKENS`가 필수이며, 없으면 서버가 시작하지 않음 |
| `ATLAS_TRUST_PROXY` | 리버스 프록시 뒤에서 `X-Forwarded-For`를 믿을 프록시 주소(`loopback`, `10.0.0.5`) 또는 홉 수(`1`). 모든 프록시 신뢰(`true`)는 거부 |
| `SNAPSHOT_DIR` | 스냅샷과 이력 저장 위치 (기본 `data/`) |
| `ACCESS_TOKENS` | 접근 토큰 목록. 형식은 아래 참고 |
| `ATLAS_COLLECT_MINUTES` | 자동 수집 주기(분). 기본 60, 0이면 끔 |
| `ATLAS_AWS_ROLE_NAME` | AWS 계정마다 맡을 읽기 전용 역할 이름. 지정하면 로그인한 역할은 전환만 하고 자원을 직접 읽지 않음 |
| `ATLAS_AWS_ACCOUNTS` | Organizations를 읽지 못할 때의 계정 목록 (`이름=ID,이름=ID`) |
| `ATLAS_GCP_BILLING_TABLE` | BigQuery 결제 내보내기 테이블 (`프로젝트.데이터셋.테이블`) |
| `ATLAS_COST_HOURS` | 비용 조회 주기(시간). 기본 24 |
| `ATLAS_STALE_HOURS` | 이 시간보다 오래된 클라우드 데이터를 '오래됨'으로 표시. 기본은 수집 주기의 3배(최소 3시간), 자동 수집을 끄면 24 |

## 접근 제어

실제 데이터 모드는 기본적으로 닫혀 있습니다. 팀이 함께 쓰는 공유 서버는 `ATLAS_HOST`로 주소를 열고 `ACCESS_TOKENS`를 반드시 지정합니다. TLS는 리버스 프록시(nginx, 사내 L7 등)에서 처리하고 `ATLAS_TRUST_PROXY`에 그 프록시를 지정해야 접근 기록과 로그인 시도 제한이 실제 사용자 주소를 기준으로 동작합니다. `npm run live`처럼 127.0.0.1에만 열 때를 제외하면, `ACCESS_TOKENS`가 없을 때 데이터를 제공하지 않습니다.

```bash
ACCESS_TOKENS='[{"name":"ops","tokenSha256":"<토큰의 sha256>","scopes":["*"],"roles":["operator","auditor"]},{"name":"감사","tokenSha256":"<토큰의 sha256>","scopes":["*"]},{"name":"team-a","tokenSha256":"<토큰의 sha256>","scopes":["<구독 또는 계정 ID>"]}]'
```

토큰 원문은 저장하지 않습니다. `scopes`를 제한한 사용자에게는 서버가 해당 범위의 자원만 보냅니다. 응답은 허용한 필드만 골라 만들며, 다른 범위의 ID가 들어 있는 수집 경고·일부 누락 목록·연결 메시지는 보내지 않습니다.

`scopes`는 무엇을 볼 수 있는지, `roles`는 무엇을 할 수 있는지를 정합니다. 전체 범위(`*`)만으로는 관리 동작이 허용되지 않습니다.

| 역할 | 허용 동작 |
|---|---|
| (없음) | 범위 안의 인벤토리 조회 |
| `operator` | 수집 실행, 수집 상태 조회 |
| `auditor` | 포털 접근 기록 조회 |

역할은 `scopes`가 `["*"]`인 토큰에서만 효력이 있습니다. 수집 상태와 접근 기록에는 모든 범위의 정보가 담기기 때문입니다. 거부된 요청은 접근 기록에 남습니다. `ACCESS_TOKENS` 없이 127.0.0.1에만 여는 단일 사용자 모드는 기존처럼 모든 동작을 허용합니다.

> 이전 버전에서 `scopes: ["*"]` 토큰으로 수집을 실행하거나 접근 기록을 보던 경우, 이제 `roles`를 함께 지정해야 합니다. SSO는 사내 IdP에 맞춰 `server/auth.ts`를 교체해 붙이는 것을 전제로 합니다.

## 상태 점검

`/api/health`는 프로세스가 응답하는지만 알립니다. 공유 서버의 로드 밸런서나 모니터링에는 `/api/ready`를 쓰세요. 데이터 폴더와 접근 기록에 실제로 쓸 수 있는지 확인하고, 둘 중 하나라도 안 되면 503을 돌려줍니다. 접근 기록 쓰기에 실패하면 그 횟수가 남고, 다음 기록이 성공할 때까지 준비 안 됨으로 표시되며, 접근 로그 화면에도 경고가 뜹니다. 오래된 클라우드 데이터 수(`data.stale`)도 함께 알리지만 준비 상태를 떨어뜨리지는 않습니다. 응답에는 오류 코드만 담기고 경로는 담기지 않습니다.

## 저장소

스냅샷은 새 파일을 완전히 쓴 뒤 한 번의 이름 바꾸기로 교체하므로, 저장 중 실패하거나 프로세스가 종료돼도 마지막 정상 스냅샷이 유지됩니다. 같은 데이터 폴더에서는 한 프로세스만 수집합니다(`collect.lock`). 서버의 자동 수집과 `npm run collect`가 겹치면 나중 것이 시작하지 않습니다. 이 잠금은 한 호스트 기준이며 여러 서버가 같은 폴더를 공유하는 구성은 지원하지 않습니다. 수집이 15분 제한을 넘기면 진행 중인 클라우드 요청을 취소하고, 그 작업이 끝나기 전에는 해당 클라우드를 다시 수집하지 않습니다.

`server/store.ts`의 `SnapshotStore`가 저장소 경계입니다. 지금은 파일 구현만 있어 실제 데이터를 Vercel처럼 파일을 저장할 수 없는 환경에 올리려면 데이터베이스 구현을 추가해야 합니다.

다른 서비스에 이 설계를 적용하려면 [docs/HANDOFF.md](docs/HANDOFF.md)를 보세요.
