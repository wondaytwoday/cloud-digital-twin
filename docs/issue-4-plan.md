# 2026-11-10 이슈 검토와 수정 계획

[이슈 #4](https://github.com/wondaytwoday/cloud-digital-twin/issues/4)의 ISSUE 번호를 사용합니다. 실계정 검증은 해당 이슈의 완료 조건에 따라 별도로 수행합니다.

## 검토 결과와 순서

1. **ISSUE-001 — VM 용량**: 내장표 의존 결함 확인. Azure Resource SKUs를 구독·리전별로, GCP machineTypes.get을 프로젝트·영역·크기별로 중복 제거해 조회합니다. API 값 우선, 실패 시 내장표로 폴백하며 출처·실패 사유를 남깁니다. GCP 맞춤형 타입은 명시적인 CPU·메모리 이름 형식만 계산합니다. GPU는 API나 VM 구성에 있는 값만 사용합니다.
2. **ISSUE-002 — AWS 수집 순환**: 고정된 계정 순서 때문에 뒤쪽 계정이 밀리는 결함 확인. 계정별 마지막 완료 시각을 저장하고 미수집·오래된 계정부터 실행합니다. 제한 시간 자동 증가는 실행 비용·대기 시간을 예측하기 어려워 적용하지 않고, 기존 상한과 설정을 유지하며 첫 수집·시간 초과 시 진행 안내를 개선합니다. 느린 단계 상위 기록을 보존합니다.
3. **ISSUE-003 — AWS 비용 실패**: 계정 수집 이후에 비용을 호출하고 모든 오류를 한 상태로 표시하는 결함 확인. 조직 비용 조회를 계정 작업보다 먼저 시도해 계정 시간 초과와 분리합니다. 단일 호출 실패는 계정 실패 수로 표현하지 않습니다. 권한·스로틀링·네트워크·요청 시간 초과·전체 제한 시간에 따른 생략을 구분하고 다음 수집 재시도를 유지합니다.
4. **ISSUE-004 — 분류**: 이슈에 명시된 자원·부속 타입을 정확한 타입 매핑으로 보강합니다. 부속 레코드는 원본을 보존하고 기본 숨김을 유지합니다. Resource Explorer 목록에는 보안 그룹 규칙 세부 내용이 없으므로 부모 규칙으로 추정 병합하지 않습니다. VPC 엔드포인트는 `endpoint`(네트워크 접점)로 추가해 VPC 경계나 경유 장비로 그리지 않습니다. 실제 분포 20% 목표는 실환경 재수집으로 확인합니다.
5. **ISSUE-006 — 구형 비용 캐시**: 제공자별 커버리지가 없으면 비용의 완전성을 알 수 없으므로 첫 수집에서 재조회합니다. 화면에도 검증 안 됨을 표시하고, 성공 후 정상 주기로 복귀합니다. version 1의 기존 필드는 계속 읽으며 새 메타데이터는 선택 필드로 추가합니다.

- `npm test`: 131개 통과. 신규 테스트는 크기 API·GPU·맞춤형 머신·폴백·취소, 반복 제한 시간의 계정 순환과 시각 저장·범위 제한, 조직 비용 실패 원인, 구형 빈/비어 있지 않은 캐시 복귀, 엔드포인트의 경계 없는 지도 표시를 검증합니다.

## 후속 실환경 확인

1. 수정분을 공유·검토·병합한 뒤 알려지지 않았던 Azure/GCP VM 크기와 콘솔의 실행 중 VM 합계를 비교합니다. 권한 또는 API 문제는 폴백 출처와 함께 보이는지 확인합니다.
2. AWS를 여러 회차 수집해 미수집 계정이 우선 갱신되고 완료/전체 수·느린 구간이 남는지 확인합니다. 한 계정 자체가 제한 시간보다 오래 걸리면 운영 설정이나 별도 단계 분리가 추가로 필요합니다.
3. 비용의 권한·속도 제한·네트워크·요청 시간 초과·전체 시간 초과 안내와 다음 실행 재조회를 확인합니다. 완료 계정이 없는 전체 실패는 마지막 정상 스냅샷을 바꾸지 않고 수집 상태에 사유를 남깁니다.
4. 실제 미분류 상위 타입과 제공자별 비율을 재확인합니다. 보안 그룹 규칙은 원본을 유지하고, VPC 엔드포인트가 네트워크 경계로 표현되지 않는지 확인합니다.
5. 구형 스냅샷의 첫 비용 조회 후 정상 주기로 돌아오는지 확인하고 기존 임시 비용 주기 설정은 별도로 원복합니다. 실제 설정은 이번에 바꾸지 않았습니다.
