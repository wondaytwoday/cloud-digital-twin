# 대규모 목데이터 데모

기본 예시는 `global-scale`(대규모 글로벌 조직)이다. 기존 6개 예시는 선택 메뉴와 `?scenario=standard` 같은 URL로 계속 사용할 수 있다. API에서 시나리오를 생략해도 같은 기본값을 사용한다. 실제 수집 모드에는 적용하지 않는다.

- AWS 계정 65개, Azure 구독 72개, GCP 프로젝트 71개: 자원이 있는 범위 총 208개.
- 자원 4,855개, 관계 1,581개, IAM 할당 684개, 최근 7일 활동 기록 6,000개, 6개월 서비스별 비용 항목 7,452개.
- 한국·일본·미국 3개 리전, 6개 사업부와 운영·검증·개발 환경을 기존 엔터프라이즈 조직에 추가했다.
- Azure 허브/스포크 양방향 피어링, AWS 계정 간 VPC 피어링, GCP 공유 VPC 호스트/서비스 프로젝트, VM·SQL·클러스터·보안 규칙, 중지·실패 상태를 포함한다. 기존 전용선·VPN·사내망·미해결 외부 참조도 유지한다.

모든 데이터는 코드로 생성한 가상 데이터다. API 형태의 fixture를 기존 수집·정규화·검증 경로에 통과시킨다. 구성 관계·IAM 할당을 실제 통신·실효 권한으로 표현하지 않는다. 비용·활동·사용률도 데모 값이다. 실제 계정 조회와 배포 환경의 수집기를 실행하지 않는다.

전체 JSON은 약 9.02MB이며 gzip으로 약 442KB다(시각에 따라 소폭 변동). 브라우저의 gzip 지원을 통해 함수 응답 크기를 줄이고 화면별 표현/페이지 API를 사용한다. 대규모 full 내보내기를 CLI로 조회할 때도 `curl --compressed`를 사용한다. 서버리스 응답 한도 내 gzip 크기를 회귀 검사한다. 이 수치는 실제 운영 수집 성능 보장이 아니다.

Vercel API 시작 실패 로그에서 `shared/capacity.ts`의 확장자 없는 import를 확인해 `.js`로 고쳤다. `tsx`가 이를 자동 해석해 로컬 테스트에서 놓쳤으므로, 서버리스 진입점을 일반 JS로 변환한 뒤 별도 네이티브 Node 프로세스에서 import하고 health 요청을 검증하는 테스트를 추가했다.

검증: 전체 단위 테스트 191개, 프로덕션 빌드를 포함한 전체 E2E 64개, 계정별 VM 18대 묶음 확인을 보강한 최종 대규모 데모 E2E 1개가 통과했다. 실제 클라우드에는 연결하지 않았다.
