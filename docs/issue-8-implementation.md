## 정확성을 위한 모델 보정

- 여러 NIC·서브넷에 걸친 VM·클러스터·LB·DB는 첫 서브넷 하나를 고르지 않습니다. 확인된 공통 VPC/VNet이 있을 때 그 아래에 두며, 공통 위치를 알 수 없으면 상위 위치에 둡니다. 실제 NIC 참조는 별도로 남깁니다. IAM 정책·활동 조회가 자원 조회와 다른 조직/폴더 범위를 포함하면 각 항목의 완료 범위를 따로 기록합니다. 성공한 빈 조직 정책/기록은 교체하고 실패·미조회 범위는 보존합니다.
- Azure Private Endpoint는 실제 서브넷에 있는 `endpoint`입니다. 대상 Azure SQL/Storage 같은 관리형 서비스를 해당 서브넷에 넣지 않습니다. Private Link 구성 연결을 경로 근거로 보존하며 통신 허용·성공을 뜻하지 않습니다. 새 접점은 번들에 전용 artwork가 없어 일반 접점 glyph를 사용합니다.
- 정책은 실제 경유 장비가 아닙니다. 정책·구성 참조·IAM 할당을 실제 통신이나 실효 권한이라고 표현하지 않습니다. 기존 경로 추적도 구성상 후보 경로입니다.
- 자원·계층 parent 순환을 검증 단계에서 거부합니다.

## 선택 수집 계약

항목은 `network`, `compute`, `database`, `containers`, `storage`, `inventory`, `iam`, `activity`, `cost`입니다. UI 분류의 kind/tier와 별도입니다. VM·DB·클러스터는 `network`가 함께 조회됩니다. 처음 UI 수집의 기본은 네트워크·VM·DB·클러스터·스토리지·IAM이며, 기존 body 없는 요청과 “지금 수집”은 전체 수집을 유지합니다.

```json
{"mode":"selected","items":[{"provider":"azure","item":"compute"}]}
```

- `GET /api/collect/items`: 관리자에게 항목·의존 관계와 저장된 완료 기록 제공.
- `POST /api/collect`: 관리자·`X-Atlas-Request: 1` 검사, JSON 8KB 제한. body 없음 또는 `{"mode":"all"}`은 전체. 선택 모드의 빈 배열·알 수 없는 제공자/항목·추가 필드는 400. 같은 확장 선택은 기존 실행에 합류하며 다른 선택은 409와 runId 반환.
- `itemCollection`은 제공자·범위·항목별 `state`, `attemptedAt`, `collectedAt`, 선택적 원인을 저장합니다. AWS 비용은 계정별 성공을 주장하지 않고 `organization` 조회 단위로 기록합니다. 일부 리전/서비스가 실패하면 해당 범위의 선택 항목을 보수적으로 partial 처리합니다. 리전별 실패 원인은 기존 `collectionGaps`에서 유지합니다.
- 완전한 성공 영역에서만 이전의 누락 자원을 삭제합니다. 부분 실패는 새로 확인한 자원과 누락된 이전 자원을 병합합니다. 미선택 자원·IAM·활동·요약·완료 시각은 유지합니다. 미해결 링크 대상은 기존 unresolved 참조 규칙을 따릅니다.
- 선택 수집은 전체 범위의 `scopeCollectedAt`을 새 시각으로 올리지 않습니다. `fullFinishedAt`으로 자동 전체 수집 간격을 별도로 유지합니다. 수동 비용 선택은 비용 정기 간격을 무시하며, 미선택 비용은 API를 호출하지 않습니다.
- AWS 수집은 `accountid` 필터로 해당 계정의 소유 영역을 제한하고 예상 밖 소유자가 반환되면 불완전 조회로 처리합니다. AWS storage는 Resource Explorer `ListResources.Filters.FilterString`을 사용합니다. 전체 검색의 첫 1,000개만 받는 Search로 대체하지 않습니다. [ListResources 공식 계약](https://docs.aws.amazon.com/resource-explorer/latest/apireference/API_ListResources.html), [필터 문법](https://docs.aws.amazon.com/resource-explorer/latest/userguide/using-search-query-syntax.html).
- GCP inventory 항목은 나머지 타입을 찾기 위해 전체 자산 목록을 읽고 소유 항목을 걸러 냅니다. inventory를 선택하지 않은 일반 항목은 assetTypes로 제한합니다. 선택 수집이 모든 경우의 호출 시간 감소를 보장하는 것은 아닙니다.

## 페이지 API와 캐시

`GET /api/resources`는 이름·범위·주소 검색, category/kind/state, 정렬, 부속물 포함, 제공자·범위를 적용한 뒤 1~100개 요약 행을 반환합니다. specs/rules/전체 링크 배열을 목록 행에 넣지 않습니다. `GET /api/resource?id=...`는 동일한 권한 제한 뒤 상세를 조회하며, 다른 범위의 ID는 404입니다. `GET /api/activity`는 기간·주체·종류·검색·범위별 최대 100개 활동과 전체 집계·완료 범위 정보를 반환합니다. 주체 필터는 상위 200개를 표시하고 전체 주체 수는 따로 유지합니다. CSV는 명시적으로 전체 페이지를 순회합니다.

활동의 동일성은 제공자·범위·이벤트 ID의 조합으로 판정하므로 서로 다른 범위의 같은 원본 ID를 삭제하지 않습니다.

커서는 데이터 내용 버전·필터·페이지 크기를 묶습니다. 버전 변경은 409, 조건 변경·손상된 커서는 400입니다. 브라우저는 버전 변경 시 첫 페이지를 재조회합니다. 범위 제한을 페이지 분할보다 먼저 적용합니다. 활동 기간은 조회 도중 기준이 바뀌지 않게 스냅샷 시각에 고정합니다.

`/api/topology?transport=1`의 full/reused 봉투는 기존 version 1 본문과 구별됩니다. 서버는 제한된 resources/links의 해시가 맞을 때만 재사용 메타데이터를 보냅니다. 브라우저는 이미 검증한 최대 3개 core와 최대 24개 화면을 보관하며, 로그아웃·401·새로고침은 캐시를 비웁니다. 메타데이터도 스키마 검사와 live·참조 무결성 검사를 통과해야 합니다.

첫 지도 방문은 아직 지도·경로·접근 분석에 필요한 전체 자원 core를 받습니다. 이번 변경은 서버의 전체 스냅샷 메모리 사용을 없애거나 모든 화면을 완전한 서버 표시 모델로 바꾸는 작업은 아닙니다.

## 내부 저장 형식 2와 호환

`<provider>.json`과 이력 파일은 `storageVersion: 2`, 활동을 비운 version 1 snapshot, 활동 조각의 경로·해시·행 수를 가진 내부 manifest입니다. 조각은 `activity/<provider>/<scope hash>/<UTC day>/<content hash>.json`에 최대 1,000행씩 저장합니다. 범위 이름·자격 증명을 파일 이름에 사용하지 않습니다.

1. 입력 전체를 `validateSnapshot`으로 검사합니다.
2. 조각을 임시 파일에서 rename해 확정합니다. 이미 있는 조각도 내용 해시가 일치하는지 확인합니다.
3. manifest 임시 파일을 쓰고 기존 manifest를 이력으로 복사한 뒤 현재 파일을 rename합니다. 같은 프로세스의 동일 저장 경로·제공자 저장은 순차 처리합니다.
4. 읽을 때 경로 형식·내용 해시·행 수·제공자/범위/날짜 파티션·중복 ID·live 무결성을 검사합니다. 참조한 조각이 없으면 저장 손상이며 “스냅샷 없음”으로 바꾸지 않습니다.
5. 하루에 최대 한 번, 현재/보존 이력의 참조를 확인한 뒤 24시간 이상 된 고아 조각만 정리합니다. 잘못된 manifest를 만나면 삭제를 중단합니다.

구형 version 1은 계속 읽고, 다음 정상 저장 때 새 형식을 씁니다. 전체 `/api/topology?part=full`과 JSON 내보내기는 활동을 합친 version 1입니다. 새 저장 파일을 이전 프로그램으로 읽을 수는 없습니다. 백업·이동·수동 복구 시 현재 manifest/이력과 `activity/`를 함께 보존해야 합니다. 이 저장소에 별도 자동 백업·복구 CLI는 없습니다. 다중 프로세스/호스트의 같은 폴더 공유와 전원 장애 내구성을 검증한 것은 아닙니다.

7일은 수집기의 조회 창입니다. 실패한 범위의 마지막 정상 활동을 기간이 지났다는 이유만으로 지우지 않습니다. 보존 이력이 참조하는 조각도 유지합니다. API는 요청한 기간을 별도로 필터링하고 조회 상한·이전 값 여부를 알려 줍니다.

- 전체 E2E: `npm run test:e2e -- --workers=2` 63개 통과(프로덕션 재빌드 포함). 설치 Chrome을 지정했다. 기능 60개와 운영 세션 매트릭스 3개를 함께 검증했다. 이후 조직/활동 동일성 보완까지 관련 E2E 11개와 마지막 활동·선택 수집·목록·정책 근거 4개를 추가 검증했다.
- 세션 매트릭스: 운영 모드 localhost HTTP, 127.0.0.1 HTTP, 로컬 HTTPS 프록시에서 로그인 유지·Secure/HttpOnly/SameSite·로그아웃 확인. 테스트 인증서·토큰은 합성 값이며 임시 경로에서 제거.
- 지연 체크포인트: 정상 경로에서는 materialize하지 않고 자원 읽기가 계정 수에 선형임을 검사. 캡처한 첫 완료 계정의 결과가 나중 계정 완료로 바뀌지 않음.
- 취소: 다음 페이지·대기 작업을 시작하지 않음. 취소 불응 작업은 실제 Promise가 끝날 때까지 차단하고 종료 후 재시도 성공. 로그인 확인도 동일. 강제로 가드를 풀어 SDK 작업을 중복 실행하지 않음.

## 남은 실환경 확인

실계정 API 호출 수·처리량·프록시 반복 수집, GCP 비용 첫 적재, 다른 계정 역할 전환, 대표 범위의 실제 위치·접근 근거, 실제 브라우저의 첫 지도/검색 p95는 미검증입니다. ECS 최신 ACTIVE를 구별하려면 API가 제공하는 상태 근거가 필요합니다. 취소할 수 없는 자격 증명 SDK Promise가 영구 정지하면 외부 연결 원인 해소나 프로세스 재시작이 필요할 수 있습니다. 이러한 조건을 로컬 가짜 테스트만으로 해결했다고 표시하거나 이슈를 닫지 않습니다.
