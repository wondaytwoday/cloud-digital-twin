# 이슈 #6 개선 계획

[2026-11-10 이슈 2](https://github.com/wondaytwoday/cloud-digital-twin/issues/6)의 신규 ISSUE-007~011을 최신 main `5bc0290` 기준으로 검토합니다. 기존 문서 변경은 보존합니다.

## 판단과 구현 순서

1. **ISSUE-010 성능**: 들여쓰기 없는 JSON 저장, 파일 변경을 확인하는 병합 캐시, 인증·범위 제한 후의 private ETag/304·gzip 응답을 먼저 적용합니다. 요약·목록·비용·IAM·활동 등 화면별 응답을 분리하고 방문한 응답은 클라이언트에서 재사용합니다. 화면은 필요한 데이터 로딩을 명시하며 검증은 모든 새 응답에 유지합니다. 목록의 DOM 수를 제한하고 주요 화면을 지연 로딩합니다. 이력은 최근 두 개와 일별 기준본을 제한된 기간 동안 보존합니다. 차분 저장·SQLite 전환은 복구 계약을 바꾸므로 이번에는 도입하지 않습니다.
2. **ISSUE-007 빈 비용**: GCP 결제 내보내기의 0행은 `pending`으로 표시하고 이전 금액·정상 조회 시각을 보존합니다. 다음 수집에서 재조회합니다. 며칠 지났다는 이유로 정상 전환하지 않습니다. 실제 비용 없는 환경은 명시적인 운영 설정으로 빈 성공을 허용합니다. Azure/AWS의 성공한 빈 응답 계약은 유지합니다.
3. **ISSUE-011 연결 부하**: 전체 제공자 실행 수와 제공자 공통 요청 수를 제한하고, 취소 가능한 대기열·연결 시간 초과 재시도를 적용합니다. 권한 거부·요청 중단·시간 초과·프록시 연결 지연을 구분합니다. 실제 프록시 설정과 자격 증명을 바꾸지 않습니다.
4. **ISSUE-008 수집 계층**: 근거 있는 정책·규칙은 보존하고, 부속 구성은 범위·타입별 개수와 제한된 예시로 요약합니다. 전체 부속물 수집은 명시적인 상세 모드로 제공합니다. 미등록 타입은 추정 분류하거나 버리지 않습니다. Resource Explorer의 보안 그룹 규칙 목록은 상세 수집된 규칙과 중복 저장하지 않되, 상위 그룹을 확인하지 못한 레코드는 미해결로 남깁니다. 화면에서 요약·수집 범위를 알립니다.
5. **ISSUE-009 관계도**: 워크로드는 서브넷·종류별 묶음으로 시작하고 클릭해 펼칩니다. 근거 없는 고립 자원은 기본 지도에서 제외하고 수를 안내하며 목록에 보존합니다. 디스크·연결 ID 등 구성에 실제 참조가 있는 관계만 추가합니다. IAM은 자원/범위에 대한 역할 할당으로, 방화벽은 적용 규칙 근거로 접근 화면에서 설명합니다. 규칙만으로 실제 허용 통신 링크나 실효 권한을 만들어 표시하지 않습니다. 선택 자원 중심 관계 확인을 제공합니다.

## 완료 판단

가짜 API·런타임과 합성 대용량 데이터로 원인·개선을 재현하고, `npm test`, `npm run build`, 관련 E2E를 실행합니다. 캐시 범위 격리·인증 재검사·파일 변경 무효화, 빈 비용→행 도착, 요청 동시성·취소, 요약 전후 정책 분석 일치, 워크로드 묶음·근거 없는 관계 미생성을 검증합니다. 실제 환경의 수집·프록시 포화·화면 전환 시간은 별도 후속 검증이며 실제 클라우드를 호출하지 않습니다.

부분 수집의 구성 요약은 같은 타입 일부가 새로 조회되어도 이전 개수·예시·시각을 유지합니다. 요약에는 ID 전체가 없어 정확한 합집합을 계산할 수 없기 때문입니다. 정상 수집이 끝나면 새 요약으로 교체합니다. summary→full 전환 중 부분 실패에도 이전 요약을 남깁니다. 모드 전환이나 확인된 보안 그룹 규칙 통합을 자원 삭제로 보고하지 않습니다.

이력은 직전 비교에 필요한 최근 두 파일과 UTC 일별 기준본을 합쳐 제공자당 최대 30개입니다. 일별 기준의 보관 기간은 `ATLAS_HISTORY_DAYS`(기본 30일, 최대 365일)이며 최근 두 파일은 비교를 위해 기간과 무관하게 유지합니다. 일별 파일도 복구 가능한 전체 스냅샷이며 차분 저장은 도입하지 않았습니다.

## 검증과 합성 측정

- `npm test`: **146개 통과**. 비용 대기→행 도착·정상 빈 결과 명시 설정, 캐시 단일 실행·무효화·복구, 인증/범위/압축별 ETag 격리, 대기 취소·동시성, 부분 요약 보존, 정책 분석 일치, 정확한 규칙 통합과 미해결 규칙 보존, 실제 참조·IAM 대상과 경로 분석 분리 확인.
- `npm run build`: 통과. 최종 전체 E2E도 프로덕션 빌드 후 **52개 통과**(33.0초). 1,000개 목록의 최대 100행·모바일 폭, 100 VM 묶음·검색, 접근 근거 열기, 전체 JSON 내보내기, 방문 페이지 재사용을 확인했습니다. 스크린샷도 확인했습니다.
- `git diff --check`: 통과. 실제 인증·클라우드·운영 스냅샷은 사용하지 않았습니다.

`node --import tsx scripts/bench-snapshot.ts`로 핵심 자원 2,000개 + 부속 구성 8,000개 + 활동 2,000개의 **합성 데이터**를 측정했습니다. 파일은 임시 디렉터리에서 생성·정리합니다.

반복 문자열이 많은 합성 데이터이므로 gzip 비율을 실데이터에 일반화하지 않습니다. 병합 측정에는 HTTP 전송·브라우저 렌더·실제 클라우드 수집 시간이 포함되지 않습니다. 부속 자원은 목록 API 조회 후 요약하므로 이 측정은 업스트림 API 호출 감소를 입증하지 않습니다. 목록은 가상 스크롤 대신 100행 페이지로 DOM 크기를 제한합니다. AWS IAM은 확인된 자원 정책 분석 없이 실효 자원 권한으로 확대하지 않으며 VM→DB·SaaS 호출도 근거 없이 만들지 않습니다.
